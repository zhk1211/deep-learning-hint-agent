```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAX_A = 1000000;
int freq[MAX_A + 1];
vector<int> used;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;
        for (int i = 0; i < n; ++i) {
            int x;
            cin >> x;
            if (freq[x] == 0) {
                used.push_back(x);
            }
            freq[x]++;
        }
        
        long long ans = 0;
        // equal case
        for (int v : used) {
            int f = freq[v];
            if (f >= 3) {
                ans += 1LL * f * (f - 1) * (f - 2);
            }
        }
        
        // geometric case
        // sort used to iterate in increasing order? Not necessary, but we can just iterate over all used.
        // However, if we iterate over all used as x, we might double count? No, because x < y < z strictly, and we only consider x as the smallest. So each triple is counted exactly once.
        for (int x : used) {
            int fx = freq[x];
            // b >= 2
            for (int b = 2; 1LL * x * b * b <= MAX_A; ++b) {
                int y = x * b;
                int z = y * b;
                if (freq[y] > 0 && freq[z] > 0) {
                    ans += 1LL * fx * freq[y] * freq[z];
                }
            }
        }
        
        cout << ans << '\n';
        
        // reset
        for (int v : used) {
            freq[v] = 0;
        }
        used.clear();
    }
    return 0;
}

Check: In the geometric case, we iterate over all x in used. But what if the same triple is counted multiple times? For a triple (x, y, z) with y = x*b, z = y*b, we only consider x as the smallest. Since we iterate over all x, we will find it exactly once. There is no other x that can produce the same triple because x is uniquely the smallest. So it's correct.

Also, note that b can be 1? We handled b=1 in the equal case. For b=1, x=y=z, which is the equal case. In geometric case, we start b=2, so we only get strictly increasing values. So no overlap.
